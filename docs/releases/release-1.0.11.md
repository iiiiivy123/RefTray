# RefTray 1.0.11 · 更新检查修复

修复检查更新依赖 GitHub 匿名 API，出口 IP 额度耗尽后只显示笼统 HTTP 502 的问题。保留 1.0.10 的悬浮类型提示及预识别修复。

## 本次修复

- 首选官方 Release 的 `RefTray-update.json`，正常检查不使用 GitHub API，不需要用户登录 GitHub 或配置令牌。只有旧发布尚无清单、明确返回404时，才兼容旧查询入口。
- Chrome 采集弹窗的新版提醒、设置里的检查更新、MCP 和安装下载共用后台更新查询；连续检查短暂合并，不再各自查询外部接口。
- 真正的限流显示原因和可重试时间，并遵守等待时间。访问拒绝、网络连接失败分别提示，不再都称为限制请求。
- 检查失败隐藏上次残留的安装按钮；旧版提醒缓存会迁移到新查询路径。
- 继续校验官方仓库、版本、安装包名称、长度和 SHA256。采集忙碌时拒绝更新，保留原素材、设置和记录。

## 如何更新

在 **设置 → 关于与更新 → 检查更新** 中操作。1.0.9 / 1.0.10 若因旧查询方式受限，可从[本次发布](https://github.com/iiiiivy123/RefTray/releases/tag/v1.0.11)下载完整 Windows 安装包覆盖原程序。安装后重新加载扩展并刷新作品网页；更新不要求更改素材库。

## 验证范围

更新查询、限流等待、旧发行兼容、损坏清单拒绝、官方来源和摘要、安装恢复、弹窗缓存与共享查询均有行为回归。已实际读取官方公开清单及校验文件，安装与下载实测状态见开发交接。

本版没有重新执行各平台 Chrome 点击实采。真实 SVG / 整页长截图、B站作者大批量及干净 Windows 的全部安装流程仍待验收；B站电影整片仍未支持。

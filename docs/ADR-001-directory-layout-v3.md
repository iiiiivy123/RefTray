# ADR-001：保存目录 v3，按采集入口与作品归档

- 日期：2026-11-11
- 状态：接受，已在0.5.52实施；B站与小红书原生实采通过，花瓣列表接续状态见CURRENT
- 关联：TASK 2026-11-11 保存目录方案；用户已批准 SAVE-LAYOUT-REVIEW，强调减少空目录。旧目录不迁移。

## 背景与问题

v2的列表层级重复，B站视频批量平铺在“视频”层，小红书收藏夹又多套一层。目录选择提前建立来源标记，失败也可能留下仅含标记的文件夹；设置素材库会预建四个空分类。

## 可行选择

直接改v2最少代码，但未完成旧任务恢复时会写到新位置。搬迁旧库可以统一外观，但会改变用户文件引用。新增目录版本能限定新任务，保留旧任务与旧素材。

## 决定与理由

新任务使用function-platform-v3。服务端独立目录模块决定分组和作品路径，图片/视频/文字共用；扩展只传列表身份、类型和版本。保留v1/v2解释器，不迁移旧库。新策略先算路径，实际有内容后才建立来源标记；视频失败只移除本次创建且仍为空的目录，不扫描删除旧目录。Pinterest单图和花瓣/Pinterest图片列表平铺；纯文字直接MD，不造“内容”层。

## 后果与验证

旧任务保持原位置，新任务采用新结构；同一旧作品重新发起新采集可能在新结构另存，原文件和缓存均保留。新结构内部重采、改标题与同名冲突按来源标记复用或隔离。没有新依赖/数据库迁移。验证各平台约定路径、空/失败不生成空目录、正文与媒体引用、批量返回分组、旧任务与手改文件保护；升级保留程序快照，代码恢复不删除新增素材。

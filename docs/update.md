# 更新 RefTray

公开安装包见 [Releases](https://github.com/iiiiivy123/RefTray/releases)。当前正式版为 **1.0.1**。

1. 完成或停止正在采集的任务。
2. 下载新版本的 Windows 安装包，安装到原来的程序目录。安装器会处理旧后台和本程序的 MCP 进程占用。
3. 启动「灵感采集」。
4. 打开 `chrome://extensions`，找到「灵感采集」，点重新加载，核对扩展版本。
5. 刷新要采集的网页。使用 AI 接口的用户再刷新客户端的 MCP 连接。

素材库、已有文件和设置会保留。更改程序安装位置不会搬动素材库。

## 从旧仓库版本更新

项目仓库改名为 **RefTray**。1.0.0 和更早版本若提示“更新文件来源不匹配”，直接下载 1.0.1 或更新版本的完整安装包，按上面的步骤覆盖安装一次。以后继续使用软件内更新。素材、设置和记录保留。

## 新版提醒和一键更新（0.5.49 起）

打开采集弹窗时，程序会检查 GitHub 正式版，成功检查后一天内不重复请求。发现更高版本会显示版本号和更新内容，可以稍后提醒或忽略该版本。

从 0.5.48 或更早版本升级时，先按上面的步骤运行完整安装包一次。此后可在管理页 **设置 → 关于与更新** 点击“检查更新”，再点“下载并更新”；正式新版提醒中也有同一入口。Windows 右下角托盘的“程序更新”也会打开此页。

也可以让 AI 检查并更新：`reftray_check_update` 查看正式新版，`reftray_install_update` 传入该版本号开始更新，`reftray_update_status` 查看进度或结果。三个入口与界面共用更新器。安装包同时更新后台、扩展、MCP 和运行时，保留原 MCP 启动路径；安装时会关闭旧 MCP 进程，AI 客户端重新连接后继续查询即可。

程序会核对安装包，等后台空闲后备份设置和采集记录，再完成安装与重启。素材库、手改文件和设置保留。不要在更新过程中移动程序或状态目录。完成后扩展会尝试自动刷新一次；原作品网页仍提示旧脚本时刷新该网页。AI 客户端可能需要重新连接 MCP。

只更新到更高的正式版本，不自动安装预发布版，也不会定时自动安装。没有可用正式新版或 GitHub 暂时限流时会明确提示，当前程序继续可用。更新失败的备份与安装日志保留在状态目录 `data/inspiration/updates/版本/`。

## 完整程序恢复（0.5.50起）

新安装器会在覆盖旧程序前保存完整副本并逐文件核对。新版安装或启动检查失败时，自动恢复上一版程序，再启动并核对旧版。下载失败或备份未通过时，不开始覆盖。

更新成功后想退回，可在 **设置 → 关于与更新 → 恢复上一版程序** 操作，或让 AI 调用 `reftray_restore_update`。页面会显示能退回的版本和恢复位置。恢复会关闭该安装目录的后台和 MCP；正在采集时先结束任务。

**恢复程序会保留现在的素材、设置和记录，包括更新之后新存的文件与改过的设置。** 设置和数据库备份用于故障排查，不会自动覆盖当前数据。若记录格式与旧版不兼容，恢复会停止并说明原因。

后台打不开时，在状态目录 `data/inspiration/updates/目标版本/` 双击 **RefTrayRestore.exe**。它独立于程序目录运行；管理页会记住这个位置。不要先删除更新目录、备份或素材库。失败的新程序会另行保留为程序目录旁的 `程序目录名-before-restore-*`，便于排查。

恢复完成后，按页面提示重新加载 Chrome 扩展并刷新作品网页；AI 重新连接 RefTray，原配置继续使用。恢复入口或备份校验失败时，保留现场和日志，反馈具体提示；不要删除原目录再碰运气安装。旧程序完整性检查失败时，安装器也会在覆盖前停止。

## 更新后遇到问题

- 扩展仍是旧版：重新加载后再核对它使用的扩展文件夹。
- MCP 提示连接关闭：后台启动后，在 AI 客户端重新连接 RefTray；不用重新填写命令和路径。可用 `reftray_status` 查看后台版本和 Chrome 连接。
- 后台启动失败：有完整程序备份时使用上面的独立恢复入口；保留 `data/inspiration/logs/service-errors.log` 和更新目录的 `installer.log`。

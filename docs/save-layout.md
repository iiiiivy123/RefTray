# 素材保存目录

[使用教程](usage.md) · [常见问题](use-cases.md)

下面的路径从你选择的素材库开始，使用设置中的“按平台分类（默认）”整理方式，先分功能、再分平台。文件夹由本次采集内容决定，不会提前建出所有分类。

## 先看两个例子

保存一篇小红书图文，文件会放在 `图文/小红书/图文-作品标题/`。正文 Markdown、图片和 GIF 直接放在这个作品文件夹。

批量保存 B 站分 P 视频，会放在 `批量/B站/分P采集-课程标题-示例作者/`，每一 P 一个文件夹，例如 `P03-第三讲/`。视频、字幕和文字稿放在该 P 的文件夹里。

标题重名时，文件夹名可能追加短编号。`_来源记录` 用于识别来源和去重，请与素材一起保留；它不代表版权授权。下表只列目录，省略具体文件和 `_来源记录`。

## 单篇作品

| 采集内容 | 保存目录 |
| --- | --- |
| 图片 / GIF | `图片/平台/图片-作品标题/` |
| 图文笔记 | `图文/平台/图文-作品标题/` |
| 视频 | `视频/平台/视频-作品标题/` |
| 仅提取音频 | `视频/平台/音频-作品标题/` |
| 网页纯文字 | `图文/平台/文字-作品标题_短编号.md`，不另建作品文件夹 |
| 视频仅文字稿 | `图文/平台/文字-作品标题/`，内含 SRT 和 MD |
| Pinterest 单图 | `图片/Pinterest/`，图片直接放在这一层 |

“平台”会替换为小红书、B站、YouTube、X、Instagram、花瓣、Pinterest、ArtStation、微博或其他网页。每个平台能用哪些采集方式，以当前页面显示的选项为准。

## 批量采集

批量先按入口分组，再按作品保存。作品前缀使用实际类型，例如 `图片-标题`、`图文-标题`、`视频-标题` 或 `音频-标题`；B 站分 P 固定使用 P 序号。

| 平台与入口 | 保存目录示例 |
| --- | --- |
| 小红书作者主页 | `批量/小红书/主页采集-作者/图文-标题/` |
| 小红书具体收藏夹 | `批量/小红书/收藏夹采集-收藏夹名-作者/图文-标题/` |
| 小红书主页收藏栏目 | `批量/小红书/收藏采集-用户/图文-标题/` |
| B站分 P | `批量/B站/分P采集-总标题-UP主/P03-分P标题/` |
| B站多稿件合集 | `批量/B站/合集采集-合集名-UP主/视频-稿件标题/` |
| B站 UP 主视频 / 图文 | `批量/B站/主页采集-UP主/视频或图文-标题/` |
| B站文集 | `批量/B站/文集采集-文集名-UP主/图文-标题/` |
| YouTube 频道 | `批量/YouTube/频道采集-频道/视频-标题/` |
| YouTube Shorts | `批量/YouTube/Shorts采集-频道/视频-标题/` |
| YouTube 播放列表 | `批量/YouTube/列表采集-列表名-频道/视频-标题/` |
| X、Instagram 主页 | `批量/平台/主页采集-作者/图片或图文或视频-标题/` |
| Pinterest 画板图片 | `批量/Pinterest/画板采集-画板名-作者/`，图片平铺 |
| 花瓣画板图片 | `批量/花瓣/画板采集-画板名/`，图片平铺 |
| 花瓣作者采集图片 | `批量/花瓣/主页采集-作者名/`，图片平铺 |
| ArtStation 作者作品 | `批量/ArtStation/主页采集-作者/图片或图文-标题/` |
| ArtStation 指定作品集 | `批量/ArtStation/作品集采集-作品集名-作者/图片或图文-标题/` |

表中的“图片或图文”按实际模式取一个名称，不会生成带“或”字的文件夹。批量纯文字直接以 MD 文件放在对应采集分组中，不另建每篇作品文件夹。微博和其他网页目前使用单页入口。

X 图文中的主帖 GIF、评论图片 / GIF 和文字稿放在同一个帖子目录。花瓣和 Pinterest 的批量图片保持平铺，避免一张图一个文件夹。

## 其他整理方式与旧素材

- 选择“直接展示作品”后，单篇例如 `图文/小红书-图文-标题/`；已经识别到的作品仍复用原目录。
- 当前规则从 0.5.52 开始使用。旧文件不会自动搬动，旧任务续采保持原位置；第一次按新规则重新采集旧作品时，可能新增一份副本。
- 只创建本次用到的目录。采集失败时清理由本次新建且仍为空的目录，不清理你原有的文件夹。

## 更改素材库或搬家

在设置里更改素材库，只改变之后新任务的默认位置。手动搬素材时，保留文件夹层级和 `_来源记录`，然后在设置里选搬后的同一层目录；如原目录中有存放设置和记录的 `data` 文件夹，把它留在原处。

搬完后从采集记录打开几份文件核对。程序会尝试重新关联能核实的文件；改过或缺失的文件可能仍指向旧位置，未完成任务也保留原任务路径。

开发者需要比较旧结构时，可看[目录变更记录](SAVE-LAYOUT-REVIEW-2026-11-11.md)。

# 线上接续开发

仓库为 `iiiiivy123/RefTray`，从GitHub的`main`检出当前代码；版本号以`source/extension/manifest.json`为准。先读仓库`AGENTS.md`、本目录`CURRENT.md`和`TASK.md`的当前记录。不要要求另一台机器具备维护者的本机盘符或历史worktree。

## 代码与验证

- 浏览器识别在`source/extension`；悬浮入口在`floating-save.js`和`web-actions-worker.js`，任务参数统一由`capture-options.js`处理。
- 本地后台在`source/server`；源码和用户素材、配置、数据库分开，不能将运行数据加入Git。
- 功能边界见[SPEC](SPEC.md)，检查与构建命令见[开发指南](README.md)。改共享采集代码需检查原平台回归；失败不能冒充空结果。
- 有Node的环境可运行`node --test tests/collector/*.cjs`。Python检查需要项目依赖；Windows原生、安装器、托盘和浏览器真实保存检查需Windows环境，不能用Linux测试代替。
- Windows安装包需要锁定的离线运行时、wheelhouse、媒体和编译组件；先执行依赖预检。源码不含本机构建缓存，不下载任意替代组件拼包。

## 继续验收

分别记录扩展/后台版本、网站和页面类型、预识别结果、实际点击、任务结果、落盘文件及历史记录。模拟页面和单元测试不能算网站实采通过。小红书链接可能需要从可正常访问的帖子进入，不能将失效链接直接认定为登录或解析故障。

程序更新后重新加载扩展并刷新网页。保留原素材与设置；测试可以新增记录，不删除旧素材来制造首次保存。重复时区分补齐/跳过与新下载。

## 发布与恢复

遵守[发布清单](publishing.md)。源码提交、安装包上传和Release分别核实。新版本使用独立版本号，不覆盖公开资产；Release写清实际检查和未完成项。当前授权不自动授权后续版本发布。

本地完整恢复副本和用户库不上传GitHub。线上能改代码与文档；验证本机设置、登录状态、素材或实际浏览器时，仍需连接那台机器。

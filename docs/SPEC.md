# RefTray 功能边界与验收约定

更新：2026-11-10。此文件记录已确认的项目行为和验收条件，实施进度与验证记录见 CURRENT.md。用户后续调整要求时同步修订本文。

## 使用方式

涉及下列功能时，开发前读取对应条目，说明受影响范围与保留基线；交付按条目报告实现、安装、线上验收各自状态。通用开发规范唯一归属为 C:/Users/Admin/.codex/ivy-dev-system，不在本文复制维护。

本文是项目约束，不是自动化门禁。下列未接入检查或尚未验收的项目必须如实报告，不能因文档存在就声称得到保证。

## B01 职责与数据边界

- 新任务使用 `function-platform-v3` 目录版本；历史 v1/v2 任务恢复时保留原版本。目录规则由 `destination_layout` 单点决定，`destinations` 分派版本，存储/媒体模块只在已有真实输出后提交来源标记。计算路径无写入副作用，不预建未使用分类。失败仅移除本次新建且仍为空的目录；原素材、用户文件和旧任务目录不迁移。
- 批量结果通过 `batch_directory` 明确返回分组位置，UI/任务记录不从平铺图片路径猜父目录。新规则具体命名见 [保存目录说明](save-layout.md)，长期兼容取舍见 `ADR-001-directory-layout-v3.md`。

- 展示分类与媒体传输方式分开：GIF 即使通过 MP4 视频源下载，仍属于图片/GIF。
- 预识别仅提供已加载内容的提示；正式采集负责确认目标与保存。未确认、合法空内容、解析失败必须可区分，不能一律显示“已确认 0”。
- 平台提取确认媒体归属；下载负责传输；转换负责加工；任务记录负责保存执行结果；界面展示这些结果。界面重排不得改变提取或保存规则。
- 主帖媒体与评论媒体分别保留来源、身份、所属关系。不能通过取消主帖身份校验或收集整页图片来修评论。
- 修改前确认原有样本和证据。不得为本次 X 评论或界面改动顺手重写已通过的 Pinterest 提取、GIF 转换、代理与身份校验。
- 保留范围包括全部已有平台：小红书、B站、YouTube、Instagram、ArtStation、花瓣、微博及通用网页。影响共享模块时逐平台回归，优先原成功链接；无法完成线上保存的项目单独标记。
- MCP 接单负责请求、控制和结果交接；媒体队列属于采集执行。媒体地址规则供解析、预检和下载共同调用，解析不能为取得规则而依赖保存文件、任务库和下载执行模块。
- 预扫描与正式采集共用执行互斥，预扫描使用本次独立参数；媒体解析缓存须区分输出格式、画质和字幕参数。进度与后台子任务必须匹配当前任务编号。
- 解析、下载和加工均纳入忙碌与停止管理；停止正在运行的解析进程，收到结束结果后释放占用。用户停止沿调用链保留为停止，不能转成解析失败或触发下一条后备路径。
- 每轮改动收尾检查本轮影响的依赖方向、规则归属、参数传递、任务所有权及取消/失败传播。架构检查命令在 [开发指南](development.md)；共享模块修改还须运行受影响平台的行为回归。TASK 记录发现、修复、通过项与待实测项；不新增后台定时检查。

## G01 网页 GIF

- 图片/GIF入口直接保存网页GIF；复用现有视频源下载与GIF转换能力，不要求用户切换到视频模式。
- 保留“跳过 GIF”的过滤选项。封面不能充当成功保存的GIF；转换后文件必须可解码、有有效动画帧。
- 验收样本：https://x.com/hardestgifs/status/2118096458016841912 。通过实际安装扩展的图片/GIF入口保存，核对实际文件、动画和采集记录。
- 旧素材保留。原成功目录 F:/LibLib自动化/图片/X/Hardest GIFs 🔥 - https_t.co_kIUUakEABp 是查来源与比对的基线，不授权清理或搬动。
- 当前状态：用户已确认实际安装版图片/GIF入口可用，要求冻结网页GIF链路；0.5.37不再修订该链路。保留转换与平台识别核心的文件哈希比对，新增评论分支另验。

## C01 X 评论范围与数量

- 保存评论由用户选择；数量默认10条，设置页保存默认值，弹窗更多选项允许本次覆盖，不增加主界面常驻数量项。
- 前N条按页面当前排序计算，以实际识别的不同回复计数，不按图片张数计数；纯图片回复也算。保留回复身份、作者、来源链接及配图关联。
- 不将推荐帖、广告、引用帖直接当评论；无法确认归属时报告未确认，不放宽为整页抓图。
- 目标数、实际读取数、实际保存数、跳过数与失败原因分别报告。页面计数不是已读取数；不足N条说明是未加载、不可见、读取失败还是实际不足。
- 评论GIF纳入需求，沿用跳过GIF选项；新默认跳过，保留用户已有选择。未跳过时复用既有下载转换。单项媒体失败保留已成功的文字和图片，并记录部分失败。
- 验收样本：https://x.com/iAmNihaoCat/status/2118270327348445408 。核对顺序、数量、纯图片回复、配图所属、保存文件及不足数量说明；评论GIF另用确认安全且包含该媒体的样本验证。
- 0.5.39 候选会在父帖编号已确认的回复中有界滚动补读、去重并恢复位置。关闭跳过 GIF 后，已确认的回复动图转为多帧 GIF 并附在对应评论，个别失败保留图文。自动化验证通过，真实登录回复及不同页面布局待验。

## T01 任务状态、失败与记录

- 任务是否停止执行和请求内容是否保存完整是两个不同事实。已结束不等于成功。
- TaskStore负责检查点版本和待同步记录。结束批量、单篇重试成功后消除旧失败也使用同一写入路径；界面不能直接覆盖后台版本。
- 已落盘文件在后续字幕、来源记录或采集历史失败时保留，结果附实际路径、部分完成及具体收尾原因。
- 未完成包含暂停、中断、部分保存失败；失败表示本次请求内容没有任何一项保存成功；全部待处理汇总进行中、未完成和失败；不再处理表示用户主动忽略。
- 用户点击开始并受理任务后，找不到视频、解析失败等也应留下可检索记录和原因，不能因未进入下载阶段而消失。输入校验未受理的错误须当场说明。
- 只有确实保存成功的内容计入成功，跳过或复用已有素材另作说明。用户主动跳过GIF不能算下载失败。
- 筛选须覆盖符合条件的记录，再分页；当前页为空不能被解释为全库没有匹配记录。成功任务可在采集记录检索并回到保存位置。
- 验收覆盖：全部失败、部分失败、暂停/中断、成功、用户忽略、解析前失败和跨页筛选。当前状态：0.5.37补先筛选后分页、部分失败归未完成、无成功内容的失败归失败；受理后记账原路径保留，未对所有平台的解析前失败进行完整Chrome入口验收。

## U01 工具与帮助

- 删除用户界面的Chrome实测助手入口；媒体诊断只保留一个入口和结果区，操作后结果可见，错误可见。
- 本地加工入口：视频抽帧、视频转GIF、提取音频。复用现有处理核心，保留原文件，另存结果；与网页采集分开。
- 处理参数、实际阶段、输出文件与错误均须可见；不能因为后台存在转换函数就宣称本地入口已经完成。
- 管理页语言使用中/EN按钮；采集记录与任务记录每页20条，允许翻页。
- 工具名称只显示一次；下载确认放在任务页，不出现在工具或设置页。诊断有独立侧栏入口，每页10条，筛选后回到第一页，错误详情默认折叠。
- 设置内“关于与更新”与托盘“程序更新”进入同一管理页，复用既有后台更新与恢复流程。软件帮助优先打开随包离线排版页面，保留无Markdown标记的纯文本说明。
- 当前状态：0.5.37移除实测助手用户入口、合并诊断、新增本地视频转GIF与M4A音频提取；复用已有转换核心。独立HTTP真实文件处理与管理页夹具检查通过；实际安装版新增入口仍待安装验收。

## V01 交付证据

- 本任务要求线上验收：登录Chrome及现有网络环境中的完整入口、后台结果、保存文件、记录均需核对。
- 离线测试、页面只读发现媒体源、直接调用后台、构建成功、磁盘文件同步分别提供局部证据，均不替代完整扩展入口验收。
- 源码、打包内容、实际安装、Chrome实际加载和线上验收分开报告。未经验证不得写“已修好”。
- 用户最新授权：0.5.37合入main，清理GitHub历史分支与旧测试发布，本机保留旧代码归档。最新下载和文档入口统一到main及Releases。

## B02 构建依赖前置检查（必须执行）

- 创建payload、复制运行时、安装依赖或编译安装器之前，必须先检查构建解释器、pip可用性、锁文件一致性、离线wheel完整性/哈希及目标Python/Windows架构的依赖解析。不能把“锁文件存在”当检查通过。
- 构建宿主Python至少3.11，运行包仍使用锁定的Python3.13，两者明确区分。依赖要求变化时重新验证，不能只沿用旧构建成功记录。
- 预检与正式安装必须使用同一套依赖参数、锁文件和受控pip环境；不继承用户pip安装位置/镜像/--user等默认设置，不修改用户全局配置。
- 预检失败立即停止并说明原因，不创建半成品包、不进入正式构建。临时解析目录允许创建并在退出时清理。
- 构建输入准备也隔离pip配置、检查Python版本和媒体文件；官方输入固定SHA256。正式构建在创建payload/dist之前检查csc、Inno存在且可执行。
- 提供可单独运行的检查入口，正式打包脚本也自动调用；不得依靠助手记忆或跳过检查。构建证据记录解释器、目标运行时和实际解析的依赖版本。
- 必须覆盖反例：低版本构建Python被提前拒绝；PIP_USER/配置污染被隔离；缺少wheel或哈希/依赖冲突在打包前失败。预检通过不替代最终运行包启动及使用验收。

## C09 花瓣新版画板与小红书收藏夹

- 花瓣画板支持 `/boards/<id>` 和 `/discovery/boards/<id>`；新 DIV 卡片须有同一作品编号和当前画板编号，旧链接卡片继续归属校验。推荐区及其他画板不得混入。普通详情须等待当前作品主图加载，限时失败明确提示；全屏大图路径保留。
- 小红书支持个人主页所选笔记/收藏栏目，以及 `/board/<24位id>` 具体收藏夹；只采当前收藏夹内笔记，保留卡片临时访问参数但不将其作为永久身份。收藏夹归属与笔记作者分开，返回后复核列表身份，切换列表停止并保留记录。
- 复用原批量处理、数量/跳过、暂停/继续和去重；新增入口不能跳过正文身份确认。离线回归、真实 DOM 核对、候选版 Chrome 实采分别记录。

## U02 一键更新

- 由用户点击“下载并更新”或明确要求 AI 更新后通过 MCP 启动；MCP 的检查、安装、状态查询复用同一组 updates 接口。只接受固定官方仓库的更新正式版，不接收任意安装地址，不自动降级或安装预发布。
- 下载完成核对版本对应的安装包名、长度、SHA256SUMS及可用的GitHub资产digest；失败不启动安装。网络请求保留系统代理设置，不携带页面或素材数据。
- 采集/加工/目录选择忙碌时拒绝更新；下载期间新增任务也必须在安装前重新核对。自动更新不主动停止用户任务。
- 启动器在独立进程接管更新，先通过原有安全退出通道关闭旧后台，再备份设置及SQLite一致快照、核对备份、调用原安装器。安装器只覆盖程序，素材和手改文件不搬动，不清理偏好或历史。
- 备份放状态目录 data/inspiration/updates/版本/backup-*，更新失败保留备份和安装日志。安装后核对受管文件和版本，重启后台并验证版本/状态根目录，确认后才显示完成。
- 更新包包含扩展、后台、MCP 与运行时；MCP 路径不变。旧 MCP 进程被安装器关闭后，宿主重连会使用新版文件，更新结果保留供查询。独立安装进程已接管状态后，下载线程的回执丢失不得覆盖安装进度或最终结果；写失败记录异常不得阻止恢复完整的后台。
- 扩展页面在完成后通过runtime.reload加载新文件；页面关闭期间完成则下次打开时恢复结果，每个目标版本自动重载至多一次。AI宿主对既有stdio连接的重连仍由宿主负责，不能把新程序运行等同于旧MCP连接自动恢复。
- 验收包含官方下载元数据、损坏/缺失校验、忙碌/失败、退出后安装、设置/任务/素材保留、重启、界面状态及重复请求。隔离副本验证与日常安装状态分开记录。

## A01 后台会话与MCP

- 浏览器登录会话和后台解析器分开。后台解析器不导出或读取浏览器凭据；站点返回requires authentication、not authorized等错误时归为ACCESS，保留诊断编号。
- 旧 `reftray_download_video` 多视频先返回待选择及数量，media_index 从 1 开始，一次提交一个。`reftray_download_videos` 和 Chrome 采集入口可顺序保存全部视频；Chrome 入口支持登录页面及完整采集参数。
- Chrome MCP 由扩展后台接单，弹窗关闭时继续执行；未指定参数继承设置。MCP 请求、扩展采集检查点分别保存，返回父任务号和子任务号。
- 单篇、作者/画板批量共用扩展采集器；暂停/继续/停止/失败重试保留已保存文件。结果交接失败暂存在扩展，重连后补交；后台重启保留中断记录。
- B 站视频页的分 P 选集从当前 BV 对应页面数据读取，独立按 P/CID 核对，P1/P2 不合并去重。选集顺序、跳过数量和目标数量同时适用扩展与 MCP，标题带 P 编号。有限选集结束即收尾，不扫描右侧推荐或触发作者列表翻页；UP 主列表既有行为保持。
- MCP 可按任务查看进度、结果和诊断，并按状态分页查询。成功记录包含实际保存目录；没有启动下载时明确说明。
- 本机 API 仅接受回环 Host。0.5.39 候选后台从程序目录和本机安装登记的目录核对浏览器扩展来源，再发放连接令牌。原生本机客户端沿用当前 Windows 用户的信任边界。

## U03 完整程序快照与恢复

- 覆盖前验证旧受管文件，保存程序目录完整副本、设置和 SQLite 一致备份，核对副本摘要。副本与独立恢复程序位于程序目录之外；拒绝重解析点、跨界路径和素材库位于程序内的更新。
- 更新失败自动恢复旧程序；界面、MCP 和独立恢复入口复用同一恢复流程。后台无法启动时仍能执行恢复；识别并关闭本安装的 MCP，占用不明时停止，不结束其他程序。
- 恢复先在同盘准备并核验旧程序，再交换目录。第二次重命名失败时恢复当前目录；保留被替换程序供排查。当前素材、偏好和数据库不覆盖回旧副本；数据库格式不兼容则拒绝恢复。
- 恢复后验证程序文件、旧版健康状态和状态目录，成功才记录 rolled_back。安装器后置检查失败必须返回非零；独立恢复先等安装器退出、再等旧更新器释放互斥。旧更新器不带新启动参数的重启也不得用模态窗口卡住恢复。
- 新完整安装器为旧更新器补齐快照保护；已有受管程序损坏则覆盖前拒绝。旧程序恢复后同步登记的扩展目录，AI 重新建立 stdio 连接。更新与恢复后页面显示后台/扩展版本及独立恢复位置。

## C10 范围、折叠回复与下载备用线路

- B站选集 UI 从 1 起填写起始 P，预览 P 起止范围；内部和 MCP 保留 skip_posts=N-1。当前播放 P 不隐式改变起点，续采保留原选集与参数，起始 P 超界时报错。
- B站视频页内的多稿件合集读取当前稿件已加载的完整合集目录，核对合集、分组、UP主及条目身份；按原顺序有限采集，不采推荐、不递归进入其他合集。界面为“从第几个视频开始”，内部仍使用 skip_posts=N-1；保留各稿件标题。存在多P时优先维持当前稿件的分P范围，不将P号与合集视频序号混用。
- 小红书和 Instagram 仅对当前作品、唯一可见评论区域、选定一级评论展开明确的回复按钮。每个父评论最多三次尝试，总等待45秒/80次动作；取消立即传播。到达回复数量或预算停止，未完成明确说明；不点击发送或关注。
- 备用下载地址只接受当前平台、相同路径的同一媒体轨道，最多四条。传输中断时丢弃该轨道的临时片段，从备用地址重新下载，禁止字节拼接。取消、磁盘错误、内容不符和大小上限不触发换源。保留原来源身份、文件上限和最终落盘核验。

## B03 采集编排边界

- background 持有一次任务的上下文与协调；page-reader 接收浏览器、取消、等待和服务函数，不读取任务单例。
- batch 保留列表导航与任务编排；batch-state 的计数、跳过和限额规则显式接收 job，不访问浏览器或网络。原参数、任务记录和断点格式保留。
- 恢复核心只使用标准库及现有扩展安装模块，不依赖 API、MCP 或下载器启动。MCP 是同一后台能力的入口，不拥有另一份更新/恢复状态。
